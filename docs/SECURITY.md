# Security review — implementation evidence and limits

Implemented and unit/API-handler tested: strict input schemas and mass-assignment denial, scoped grants, active appointments, MFA gate, private-case projections, independent approvals, conflict restrictions, financial precision, quorum/vote integrity, audit digests, SQLite audit update/delete protection, transactions and rollback. HTTP handlers use safe errors, trace IDs, Origin checks, request limits, same-site local session cookies, and privacy-safe exports. React renders untrusted text without HTML injection.

Appwrite mode encrypts aggregate payloads using AES-256-GCM with random nonces. Keep APPWRITE_DATA_KEY separately from Appwrite backups and retain it for restoration. A compromised API host holding this key can decrypt data; application-role restrictions do not protect against infrastructure compromise. No hardware-backed key manager or external audit anchor is implemented. Appwrite transactional behavior and MFA/session factor responses still require live verification.

Production refuses synthetic mode; Appwrite endpoint must use HTTPS and key length must be valid. The Docker process runs as an unprivileged user. Security headers include CSP, nosniff, referrer, frame and device-permission restrictions. The reverse proxy must provide HTTPS and HSTS after the actual hostname is configured.

Outstanding launch work: live evidence Storage/ClamAV verification, encrypted document version handling, role-grant institutional verification, stronger key management, independent penetration testing, dependency vulnerability assessment, denial-event auditing, security telemetry, formal retention/deletion, load/DoS testing, disaster recovery, and independent accessibility review. None is represented as complete. Full emergency dispatch, surveillance, coercive identity screening and automated criminal profiling are not implemented.

`pnpm lint` combines strict unused-code checks and a small source-policy checker; it is not ESLint or a security scanner. CI is configured but has not run remotely. Browser and external-service validation were not completed in this session because local preview approval checks timed out and no Appwrite credentials were provided. This is a development pilot, not a certified production-ready deployment.

Selected additions now implement bounded private binary uploads, signature/MIME validation, retry-safe immutable metadata, actual ClamAV INSTREAM integration, fail-closed quarantine and account-bound 60-second download tokens. Live Appwrite/scanner/container verification and file retention policy remain pending; no test scanner is enabled in the app. See ADDITIONS_GUIDE.md. Deadline notices are private and transactionally deduplicated, and tours do not grant privileges.
