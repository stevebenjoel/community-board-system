# Privacy implementation

Ordinary cases are confidential; safety cases are highly restricted. No public case narratives, identities or exact security coordinates are exposed. Public project data uses a dedicated redaction projection; unverified finance is excluded from public views. Notifications contain generic titles, no confidential narratives.

Residency collects a verification method and statement/reference, not NIN or biometrics. Only owners and scoped reviewers receive residency records. The profile supports access, correction, deletion-review, restriction and jurisdiction-change requests with operator responses. These are requests, not automatic destructive operations or promises to erase retained evidence.

Browser report drafts are optional, per-account and tab-scoped in sessionStorage; they are non-authoritative. Safety-report drafts are not stored there. Drafts are removed only after the server confirms submission. Native drafts use per-account Expo SecureStore; device verification remains pending.

Before real people use the service, the responsible operator must adopt a privacy notice, lawful bases, retention schedule, access/export procedures, data-subject response process and incident procedure. Current public notices are expressly pilot drafts. The app does not invent a legal operator or claim regulatory compliance. No real personal data is seeded.

Private binary case/project evidence is now supported. Its metadata and downloads inherit parent-record access; public project status does not make attachments public. All uploads are quarantined until a real clean scan and downloads recheck current authorization. Adopt retention/erasure and metadata-minimization policies before real use. The prototype does not promise removal of image EXIF metadata; uploaders should avoid unnecessary location/personal details. Walkthrough progress is private to the account, and deadline reminders contain no case narratives.
